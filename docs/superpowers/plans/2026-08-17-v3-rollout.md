# V3 Site Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Josh's v3 designs — revised homepage (v25) + six rebuilt section pages + light-touch restyle of remaining pages — to production.

**Architecture:** Homepage lands first as a diff against the shipped v5 layer. The six section pages are independent tasks (parallelizable, one implementer each): every page owns `app/styles/v3-<page>.css` (scoped `.v5.pg-<page>`) and a rebuilt `app/<route>/page.tsx` wired to its existing engine. The remaining dark pages get a token-overlay stylesheet (`v5-lite`). Spec: `docs/superpowers/specs/2026-08-17-v3-site-rollout-design.md`.

**Tech Stack:** Next 16.3 App Router, next/font, Sanity, Supabase, CFBD, YouTube Data API, vitest, Playwright (verification only).

## Global Constraints

- **Mockups are the pixel source of truth**, located at `wireframes/v3/<name>.html` (Task 1 moves them there). Read your page's mockup in full before writing code.
- **§0.1 honesty:** every name/number/record in a mockup is fictional. Live engine data or honest fallback (`EmptyState` / count-free copy / omission); fictional content only under `DEMO_MODE` (`lib/demo.ts`). Mockup-marked placeholders (e.g. "FLIP WATCH — PLACEHOLDER names") must not ship in production.
- **CSS scoping:** page styles live ONLY in your own `app/styles/v3-<page>.css`; selectors scoped under `.v5.pg-<page>` (page `<main className="v5 pg-<page>">`). Never edit `app/v5.css`, `app/globals.css`, another page's stylesheet, or `app/layout.tsx` (imports are wired centrally in Task 8). Apply the v5 CSS Porting Recipe (`docs/superpowers/plans/2026-08-16-homepage-v5.md`): convert element selectors to classes, prefix `@keyframes` with the page slug, add `position:relative` fill-anchors for `next/image` `fill`, and neutralize globals.css bleed-through — known offenders `nav`, `footer`, `section`, `.wrap`, `.eyebrow`, `.btn`, `.wire`, `.feat`, `.game`, `.duo`, `.show-grid`, `.card`, `.panel`, `.thread`, `.hero` (globals sets `section{padding:40px 0}`, `.btn{border:1.5px solid…}`, etc. — redefine every property your design depends on).
- **Preserve:** route paths, `export const metadata`, JSON-LD blocks, canonical URLs, auth/session components, detail routes (`/notebook/[slug]`, `/community/[board]`, `/community/thread/[id]`, `/play/*`, `/wire/[slug]`), and sitemap entries.
- **Images:** `next/image`; remote hosts already configured: `*.ytimg.com`, `a.espncdn.com`, `cdn.sanity.io`. No new hosts. `/_next/image` 404s locally (custom loader) — expected; image verification happens in production.
- Existing client components (ballot form, pick'em forms, composer, `NavSession`) are re-mounted/re-skinned, not rewritten, unless the mockup makes that impossible — then the smallest possible change.
- Verify each task with `npx tsc --noEmit`; commit per task with a `feat(v3-<page>): …` message + the Claude co-author trailer.
- Mirror repo patterns for any Next API; consult `node_modules/next/dist/docs/01-app/` before using an API the repo doesn't already use.
- Local server: kill with `pkill -f next-server`.

## Data cheat-sheet (exact signatures)

- **YouTube** (`@/lib/youtube`): `getVideos(): Promise<Video[]>` (`Video {id,title,published,thumbnail}`), `isEpisode(v)`, `getShorts(limit): Promise<Short[]>` (`Short {id,title,published}`), `shortsThumb(id)`, `videoUrl(id)`, `getChannelStats(): Promise<ChannelStats|null>` (`{subscribers,videos,views}`), `compactCount(n)`, `CHANNEL_URL`, `SUBSCRIBE_URL`, `APPLE_PODCASTS_URL`, `SPOTIFY_URL`, `SOCIAL_LINKS`.
- **Sanity** (`@/lib/sanity`): `getPublishedArticles(limit)`, `getArticleBySlug(slug)`, `getWireItems(limit)`, `getWireStories(limit)`; `SanityArticle {_id, slug.current, headline, dek?, byline, publishedAt?, heroUrl?, episode?.series?}`, `SanityWireItem {_id, headline, category?, teams?, publishedAt, storySlug?, sourceUrl?, sub?}`.
- **JP Poll** (`@/lib/jp-poll`): `getCurrentBoard(): Promise<JpBoard|null>`, `getLatestPublished(): Promise<JpBoard|null>`, `getBoardResults(boardId): Promise<JpResultRow[]>`, `getBallotCount(boardId): Promise<number>`, `boardOpenForVoting(b)`, `jpClient()`.
- **Play** (`@/lib/play`): `getCompetitions(): Promise<Competition[]>`, `getCompetition(slug)`, `getEntryCount(slug): Promise<number>`, `getLeaderboard(...)`, `compLocked(c)`, `playClient()`; types `PickemGame`, `Competition`, `PlayEntry`.
- **Recruiting** (`@/lib/cfbd`): `getRecruitingRankings(): Promise<{year, ranks: RecruitingRank[]}|null>`, `getTeamDirectory()`, `isCfbdConfigured`.
- **Community** (`@/lib/community`): `getBoards(): Promise<Board[]>`, `getThreads(db, {board?, limit?}): Promise<ThreadSummary[]>`, `getTrendingThreads(limit)`, `publicClient()`; `ThreadSummary {id, board_slug, title, thread_type, pinned, locked, hidden, reply_count, view_count, last_reply_at, created_at, author_label, citizens?}`.
- **Shared UI:** `RelTime` (`iso` prop), `EmptyState` (`kicker,title,body,cta?`), `formatDate`, `teamLogoUrl(slug)`, `slugifyTeam`, `createArtPicker()`, `PreseasonChip`, `DEMO_MODE`.

### Task 9: v5-lite overlay for remaining pages

**Files:**
- Create: `app/styles/v5-lite.css`
- Modify: the top-level wrapper of each remaining page to add `v5-lite` (routes: scores, teams + `teams/[slug]`, wire + `wire/[slug]`, tailgate, shop, playoffs, report, about, ledger, porch, search, standards, privacy, terms, contact, me, join, welcome, authors)

- [ ] **Step 1:** Write `app/styles/v5-lite.css` — a token overlay, no structural rules:

```css
/* v5-lite: light-editorial token overlay for pages without v3 mockups.
   Re-maps the chalk theme variables inside any .v5-lite subtree. */
.v5-lite{
  --paper:#FFFFFF; --paper-2:#F4F6F9; --ink:#14181F; --ink-dim:#5B6472;
  --line-l:#E4E8EE; --lamp:#C9A227; --lamp-deep:#A8861B;
  background:var(--paper); color:var(--ink);
}
/* dark bands inside lite pages keep chalk text but adopt v5 navy */
.v5-lite .on-dark, .v5-lite .cta-band{--chalk:#F4F6F9; --chalk-dim:#B9C6D8; --line-d:rgba(255,255,255,.14); background:#0E2240;}
.v5-lite .eyebrow{font-family:var(--v5-cond-f),sans-serif;font-size:10.5px;letter-spacing:.24em;color:var(--lamp-deep)}
.v5-lite .display{font-family:var(--v5-sans-f),sans-serif;font-weight:800;letter-spacing:-.01em;text-transform:none}
```

Import in `app/layout.tsx` after the v3 imports. Then iterate: render each route, adjust ONLY within `v5-lite.css` (plus adding the class to page wrappers). This is best-effort — a page that reads worse with the overlay keeps its dark layout (remove the class) and goes on the exceptions list.

- [ ] **Step 2:** Add `v5-lite` to each route's `<main>` (or top wrapper). `npx tsc --noEmit`.
- [ ] **Step 3:** Screenshot-review at least: /scores, /teams, /wire, /tailgate, /shop, /playoffs, /report, /me, /join. Remove the class wherever it degrades the page; record removals.
- [ ] **Step 4:** `npm run build` clean. Commit `feat(v3-lite): light token overlay for non-mocked pages`.
